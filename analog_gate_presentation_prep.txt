================================================================================
เตรียมพรีเซนต์โปรเจค "Analog Gate"
================================================================================

--------------------------------------------------------------------------------
ส่วนที่ 1: สรุปข้อมูลโปรเจค "Analog Gate" สำหรับการพรีเซนต์
--------------------------------------------------------------------------------

1. ภาพรวมปัญหา (Problem Statement)
- Dopamine Dependency: วัยรุ่นปัจจุบันเสพติดสื่อวิดีโอสั้น (Short-form videos เช่น TikTok, Shorts) ทำให้เกิดภาวะ "Popcorn Brain" (สมาธิสั้นลง, อ่านจับใจความยากขึ้น)
- ข้อจำกัดของแอปจำกัดเวลาเดิมๆ: แอปจัดการเวลาหน้าจอทั่วไป แค่ขึ้นแจ้งเตือน หรือใส่รหัส ซึ่งผู้ใช้สามารถกดข้ามหรือหลีกเลี่ยงได้ง่ายเกินไป ทำให้หยุดพฤติกรรมไถหน้าจอไม่ได้จริง
- ปัญหาเนือยนิ่ง (Sedentary Habits): ทำให้เกิดปัญหาสุขภาพทางกายตามมา เช่น ออฟฟิศซินโดรม, สายตาเสีย

2. แนวทางการแก้ปัญหา (The Solution)
แอป Analog Gate คือ AI Dopamine Gatekeeper ที่ใช้ทฤษฎี "Intentional Friction" (สร้างความยุ่งยากอย่างตั้งใจ) และ "Delayed Gratification" (การชะลอความพึงพอใจ) เพื่อดึงผู้ใช้กลับสู่โลกจริง

3. การทำงานหลัก (Core Mechanisms)
- The AI Gatekeeper: เมื่อผู้ใช้เล่นแอปที่ตั้งไว้เกินเวลา ระบบ Android Background Service จะตรวจจับและทำการสร้าง "หน้าจอล็อก (Overlay)" ทับแอปนั้นทันที ผู้ใช้ไม่สามารถกดปิดได้
- Active Mission: เพื่อปลดล็อก ผู้ใช้ต้องทำภารกิจใน "โลกจริง" เช่น ไปเดินเล่น, อ่านหนังสือเล่มจริง, หรือหาต้นไม้ แล้วถ่ายรูปยืนยัน
- Real-time AI Verification: แอปจะบังคับให้ถ่ายรูปสด (ห้ามอัปโหลดจาก Gallery) และส่งให้ Gemini AI ตรวจสอบภาพเพื่อกันการโกง หากไม่มีเน็ต จะมีระบบ ML บนเครื่อง (Google ML Kit) ทำงานแทน
- Gamification: หาก AI อนุมัติ (Verified) หน้าจอจะปลดล็อก เวลาจะถูกรีเซ็ต และผู้ใช้จะได้รับ XP หรือสะสม Streak เพื่อสร้างแรงจูงใจเชิงบวก

--------------------------------------------------------------------------------
ส่วนที่ 2: การพัฒนาเทคโนโลยีและสถาปัตยกรรม (Technological Development)
--------------------------------------------------------------------------------

1. กระบวนการคิดและพัฒนา (The Development Process) - อิงจาก Design Thinking 5 ขั้นตอน
- Empathize (ทำความเข้าใจผู้ใช้): เริ่มจากการทำแบบสอบถามและสังเกตพฤติกรรมของวัยรุ่นที่ติด Short-form Video ทำให้พบปัญหา "Popcorn Brain" และพบว่าแอปจัดการเวลาแบบเดิมๆ ไม่ได้ผล
- Define (กำหนดปัญหาชัดเจน): สรุปได้ว่าต้องการระบบที่แทรกแซงทางกายภาพ (Physical Intervention) ที่ต้องทำงานระดับระบบปฏิบัติการ (System-level) เพื่อสกัดกั้นการเล่นแอปแบบบังคับ
- Ideate (ระดมสมองหาทางแก้): เกิดเป็นแนวคิด "AI Dopamine Gatekeeper" ที่ต้องใช้ AI มาบังคับให้ผู้ใช้ไปทำกิจกรรมในโลกจริง
- Prototype (สร้างต้นแบบ): ใช้ Flutter เป็นโครงร่าง, ต่อกับ Native Android API เพื่อทำการล็อกหน้าจอ และฝัง Gemini AI ลงไปเพื่อทำระบบตรวจสอบรูปภาพ
- Test (ทดสอบและปรับปรุง): นำไปทดสอบจริง เก็บ Data Log นำมาปรับแต่งความแม่นยำของ AI (Prompt Tuning) ลดอัตราการปฏิเสธภาพผิดพลาด และจัดการเรื่องการกินแบตเตอรี่

2. เจาะลึกสถาปัตยกรรมทางเทคโนโลยี (Deep Dive Tech Stack)
- Pillar 1: Frontend & State Management
  * Flutter: สร้าง UI ที่สวยงาม ลื่นไหล และรองรับการทำ Cross-platform (iOS/Web) ในอนาคต
  * Riverpod: จัดการ State ที่ซับซ้อน (เวลานับถอยหลัง, สถานะการล็อก, การรอ AI) ทำให้ UI อัปเดตแบบเรียลไทม์โดยที่แอปไม่ค้าง

- Pillar 2: Android Native Integration (ระบบล็อกหน้าจอ)
  * UsageStatsManager API: ทำงานเป็น Background Service เพื่อดักจับว่าผู้ใช้กำลังเปิดแอปพลิเคชันไหนอยู่ (Foreground app) และเปิดมานานแค่ไหนแล้ว
  * SYSTEM_ALERT_WINDOW API: วาดหน้าจอล็อก (Overlay Locker) ขึ้นมาบังแอปตัวนั้นทันที เป็นหน้าจอระดับ System-level ที่ผู้ใช้กดทะลุไม่ได้

- Pillar 3: AI & Machine Learning Engine (ระบบตรวจสอบ)
  * Gemini AI API (Cloud-based): ตรวจสอบภาพสดแบบ Real-time มีการทำ Prompt Engineering เพื่อกันโกง (เช่น ตรวจจับรูปจากหน้าจอคอม) 
  * Google ML Kit (On-device Fallback): รัน Offline หากไม่มีเน็ต ช่วยจำแนกวัตถุเบื้องต้นในภาพเพื่อปลดล็อกชั่วคราว

- Pillar 4: Backend & Gamification
  * Supabase (PostgreSQL): เก็บข้อมูลที่มีความสัมพันธ์กัน (Relational Database) 
  * Gamification: เก็บประวัติภารกิจ (Mission Logs), คำนวณ XP, บันทึก Streaks ทำให้การปิดแอปกลายเป็นความรู้สึกท้าทายเหมือนเล่นเกม

--------------------------------------------------------------------------------
ส่วนที่ 3: เตรียมพร้อมตอบคำถามเชิงเทคนิค (Technical Q&A Preparation)
--------------------------------------------------------------------------------

Q1: ระบบรู้ได้อย่างไรว่าผู้ใช้กำลังเล่นแอปไหนอยู่ และไปล็อกแอปนั้นได้อย่างไร?
A: เราใช้ API ที่ชื่อว่า `UsageStatsManager` รันเป็น Background Service คอยเช็คว่าแอปใดทำงานอยู่เบื้องหน้า (Foreground) เมื่อเวลาเกินกำหนด จะใช้สิทธิ์ `SYSTEM_ALERT_WINDOW` เพื่อสร้าง Overlay บังหน้าจอทั้งหมด

Q2: ป้องกันผู้ใช้ "โกง" ระบบอย่างไร?
A: แอปบังคับให้เปิดกล้องถ่ายภาพสดเท่านั้น ห้ามอัปโหลดจาก Gallery และใช้ Prompt Engineering กับ Gemini AI ตรวจสอบบริบทภาพ เช่น หากเป็นรูปหน้าจอคอมพิวเตอร์ หรือภาพไม่สอดคล้องกับภารกิจ ระบบจะ Reject ทันที

Q3: ถ้าไม่มีอินเทอร์เน็ต จะปลดล็อกหน้าจอได้ไหม?
A: มีระบบ Fallback คือ Google ML Kit (Image Labeling) แบบ On-device ทำให้วิเคราะห์วัตถุเบื้องต้นแบบ Offline ได้ ช่วยให้แอปทำงานต่อได้โดยไม่ต้องพึ่งเน็ตตลอดเวลา

Q4: ทำไมถึงเลือกใช้ Flutter + Riverpod?
A: Flutter ช่วยสร้าง UI ข้ามแพลตฟอร์มได้รวดเร็ว ส่วน Riverpod จัดการ State ระดับ Compile-time ได้ปลอดภัย เหมาะกับแอปที่ต้องจัดการ State ซับซ้อนสลับไปมา เช่น การล็อกหน้าจอและรอ AI

Q5: ทำไมถึงเลือกใช้ Supabase แทน Firebase?
A: Supabase ใช้ PostgreSQL (Relational Database) ซึ่งตอบโจทย์ข้อมูลที่มีความเชื่อมโยงกัน เช่น ข้อมูล User เชื่อมกับ Mission History และระบบ XP/Streak ได้ดีกว่า NoSQL ของ Firebase

Q6: ระบบ Overlay ละเมิดนโยบายของ Google Play Store ไหม?
A: สิทธิ์ `SYSTEM_ALERT_WINDOW` เป็นสิทธิ์ละเอียดอ่อน แต่ใช้ได้หากชี้แจงชัดเจน แอปจัดอยู่ในหมวด Digital Wellbeing ซึ่งฟีเจอร์นี้จำเป็น เราจะอธิบายและให้ผู้ใช้กดอนุญาตเองในหน้า Onboarding

Q7: อนาคตจะทำลง iOS ด้วยไหม?
A: วางแผนไว้ แต่อาจท้าทายเพราะ iOS มีระบบ Sandboxing เข้มงวด ไม่อนุญาตให้ทำ Overlay อิสระแบบ Android อาจต้องเปลี่ยนไปใช้ Screen Time API ของ Apple ซึ่งจำกัดการปรับแต่ง UI มากกว่า
